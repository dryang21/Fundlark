# Fundlark v4.5: cross-disciplinary terminology and UI redesign

## Goals

Researchers should find a funding opportunity, assess its constraints, and manage an application without unnecessary scrolling or decorative UI. This version focuses on clearly separating **research relevance**, **applicant eligibility**, and **source freshness**. The design uses a restrained editorial layout, compact results, and obvious next actions rather than a marketing-style dark hero. Its visual references were the *information hierarchy* of Agent Skills documentation (https://agentskills.io/home) and the *search-first workflow* of OpenAlex (https://openalex.org), not a reproduction of their brand assets.

## User experience

1. **Profile.** One research description, an automatically generated editable keyword list, optional taxonomy browser, career-stage-aware details, and always-visible optional society/institution fields.
2. **My funding.** All matched records, source and eligibility filters in the same area, and application tracking. Research relevance is not an eligibility determination.
3. **Explore.** A general catalog with a homepage shortcut, fixed ten items per page, and independent source/discipline filters.

The homepage deliberately puts an actionable search box first; search input is transferred into the Explore field and invokes the same existing filtering logic. Examples are tucked into an optional disclosure.

## Terminology architecture

- `docs/demo/research-vocabulary.json`: curated, auditable seed with **959 terms across 21 broad field groups**, aliases, related terms and subfield metadata.
- `docs/demo/research-seed.mjs`: static generated bundle used in the browser; no network dependency.
- `docs/demo/taxonomy.mjs`: phrase normalization, longest-phrase-first extraction, synonyms, lower-weight related topic suggestions, optional OpenAlex import and field browser.
- `docs/demo/manual-profile.mjs`: conservative spell checking and editable keyword precedence. User descriptions are never silently rewritten.
- `scripts/update_openalex_taxonomy.py`: maintainer-operated source importer. Run only with explicit network access. The optional `docs/demo/openalex-topics.json` is only loaded locally after it has been imported.

An optional import can retrieve OpenAlex's hierarchy from its public API, using a free API key when needed. Example:

```bash
python3 scripts/update_openalex_taxonomy.py
# If higher quotas are required:
OPENALEX_API_KEY=YOUR_KEY python3 scripts/update_openalex_taxonomy.py
```

Full OpenAlex classifications are **not included in the ZIP** by default, and the curated 959 terms are not claimed to be exhaustive. Research topics classified from publications are not equivalent to official grant sponsor research categories. The optional importer downloads topic metadata only, never a user's profile text.

## Privacy, accuracy, limitations

The research description and saved applications stay in the user's browser. The vocabulary search and text normalization are local. If a user explicitly requests an institution registry search or opens external links, those separate operations follow their own behavior. A typo corrected for matching is visible in editable keyword chips; technical names and unknown acronyms should stay unchanged. The funding catalog has not been refreshed as part of v4.5. The three eligibility statuses are decision aids based on incomplete indexed rules—not confirmations from sponsors.

## Testing

Run from the project root:

```bash
node --test tests-js/*.test.mjs
pytest -q
```

Two optional worker integration tests require the Cloudflare Wrangler development dependency. Code-only and static-browser rendering checks are not equivalent to a full live deployed acceptance test.
